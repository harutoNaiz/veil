- Deviations from the spec and why:
  1. **Android licences (spec 4/7, step 4 of the algorithm).** cmdline-tools 23.0 prints "The --licenses option is no longer needed" and exits 0 without writing a licence file. It accepts and writes `licenses\android-sdk-license` itself during `sdkmanager --install` (verified on a fresh empty SDK root: install of platform-tools alone created the file). The bootstrap therefore still runs `--licenses` with `y` input (harmless), and checks the licence file after the install step instead of right after `--licenses`. It still logs the licence file names. Licences are still accepted on the user's behalf (R10).
  2. **R4: `override-dependencies = ["huggingface-hub==2.1.1"]` in `[tool.uv]` of `pyproject.toml`**, with a comment. Reason: transformers 5.18.0 (ml group) needs tokenizers >=0.23.1, which declares huggingface-hub <2.0, while the main pin is huggingface_hub 2.1.1. Verified: `uv lock` without the override fails with "No solution found". Moving an ml pin does not help (older transformers 5.x use older tokenizers that cap hub even lower), and the spec says main pins stay. All 4 ml pins and all main pins are unchanged. transformers itself allows hub <3. To remove once tokenizers lifts its cap.
  3. **Bootstrap check table output** shows the version plus the full tool path for uv, java and adb (`0.12.21 @ D:\veil-toolchain\uv\uv.exe`) and is not truncated, so "paths under D:\veil-toolchain" can be seen. The pass/fail logic is as in the spec.
  4. `console/.idea/` and `*.iml` exist locally (made by `flutter create`); they are git-ignored by the root `.gitignore`.
- Notes: Gradle prints "SDK XML versions up to 3 ... version 4 was encountered" for both apps. It is a warning from AGP 9.1.0's SDK reader about the newer cmdline-tools and does not affect the build. Both builds also pass with the repo path containing a space (R1 did not materialise).
