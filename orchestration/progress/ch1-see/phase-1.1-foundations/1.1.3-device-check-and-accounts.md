- How it works:
  - The Test Feed shows 60 placeholder items in a `ScrollView`. Each display frame in which the scroll position changed, it writes one JSON line (`frame`) with the rectangle of every visible item, in screen pixels, to `filesDir/feedlog.jsonl`. It also writes `session` (item layout, viewport), `tap` and `pause` lines. The geometry and the JSON are plain Kotlin with JVM unit tests (12 tests).
  - `parse.py` holds pure parsers (adb devices, getprop, wm size/density, meminfo, refresh rates, resumed activity, the `VEIL_HELLO` line, RAM marketing size, chip match, OS skin, the property allowlist). `adb.py` wraps adb. It refuses to install, stop or `run-as` any package other than the three Veil ones, validates every value it puts in a shell command, and keeps the serial out of error messages.
  - `device_profile.py` reads only allowlisted properties plus meminfo, `wm size`, `wm density` and the fps lines of `dumpsys display` (identifier fields removed), builds a `DeviceProfile`, renders `docs/device-profile.md` and, with `--write`, adds or replaces the "Target chip check" entry between its two markers in `docs/decisions.md` (next free D-number, so D-004). Without a phone it exits 3 with `no adb device (connect the phone: HC-002)`.
  - `bench_check.py` runs the 13 lines in order, one at a time, prints `[STATUS] id detail` in ASCII, writes `bench-check.txt` and `bench-check.json`, and exits 0 / 1 / 2 as in the spec. Lines that need the phone or a token SKIP with the reason text from the spec; an exception in a line becomes a FAIL, not a crash.
- Deviations from the spec and why (all small):
  1. **Fixture file names.** `device_profile.from_dir` reads `getprop-filtered.txt` (RAW_FILES), but the spec's fixture list says `getprop.txt`. Both are provided: `getprop.txt` is a full synthetic dump including a fake serial and other keys that must be dropped, and `getprop-filtered.txt` is exactly what `filter_props` keeps from it (a test checks that). Also added `fixtures/sm8850/captured-at.txt` and a fixtures README.
  2. **`captured-at.txt`.** `--evidence-dir` also saves `captured-at.txt`, and `from_dir` reads it (falls back to the file's mtime), so a profile rebuilt from saved evidence keeps its capture time and the tests are deterministic. RAW_FILES itself is unchanged.
  3. **`MultipleDevicesError`** is a subclass of `AdbError` (so `device_profile` can exit 4 without parsing messages). `adb.tap()` was added for `drive tap`.
  4. **`FeedGeometry.hitTest`** was added to the spec's `FeedGeometry` (used for taps; unit-tested). `RulerView` draws its ticks along the left edge and also the top edge.
  5. **`toolchain` line runs bootstrap without `VIRTUAL_ENV`.** Under `uv run` that variable is set, and bootstrap's `uv python find 3.11.16` then reports the repo `.venv` instead of the toolchain Python, so the `python` row failed (`BOOTSTRAP FAILED: python`) even though `bootstrap.ps1 -CheckOnly` run directly passes. `tools/bootstrap.ps1` is 1.1.1's file and was not touched; the fix is in `bench_check._line_toolchain` (a test covers it). The 1.1.1 orchestrator may want to know that bootstrap's python row is sensitive to `VIRTUAL_ENV`.
  6. **`update_decisions` and the placeholder.** On a first insert it replaces the comment `<!-- The target-chip check (D-004 or later) is appended by ... -->` that 1.1.1 left at the end of `docs/decisions.md` (otherwise it appends at the end); the markers make later runs replace the block. If `decisions.md` does not exist in `--docs-dir`, it is created with a `# Decisions` heading. Line endings of the file are kept. It was not run on the real `docs/decisions.md` (the spec says not tonight); `git status` shows `docs/decisions.md` untouched.
  7. `parse_wm_density` lets an "Override density" win over the physical one, like `wm size` (the Guard reads the live value).
  8. Lines that depend on the phone say `adb not PASS (<reason of the adb line>)` when skipped.
  9. `hf.anonymous_probe` silences the Hugging Face "unauthenticated requests" and "no symlinks" warnings, which otherwise print on stderr and look like errors in PowerShell.
  10. Extra tests beyond the spec (adb safety rules, a11y list helpers, bench_check flag and failure cases, CRLF handling in `update_decisions`). Python code was formatted with `ruff format` to the project's 100-column setting.
- Not run (needs the phone or a token; code is written and unit-tested against fixtures and monkeypatches only): any real adb call (`collect`, `install_if_changed`, `launch`, `screencap`, `run_as_cat` and so on), the `scrcpy`, `guard-app`, `console-app` and `testfeed` lines, `aihub.tiny_profile` and `family_devices` against the real service, and `a11y_probe enable/disable` (never to be run during the build). Rows P1 and P2 are pending HC-002 and HC-003.
- Side effect to know about: running `adb devices` starts the adb server daemon (`adb.exe`) in the background. It is harmless and shared with scrcpy; `adb kill-server` stops it.
