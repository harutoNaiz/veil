## What was asked
JSON Schemas (draft 2020-12) for the 16 shared types (Rect, Frame, UiEvent, Region, Embedding, Concept, ConceptPack, CompiledConcept, Finding, Track, Mask, MaskPlan, Feedback, ModelManifest, EngineStats, ScreenLabel) with the conventions, `contractVersion` and the `spaceId` rule written into each schema. Also generated pydantic v2 models, 2-3 valid and 1-3 invalid examples per type, a validator CLI, cross-field rules, a README for owner review, and tests that validate all of it. See SPEC section 4 (1.1.2).

## What was implemented            (Builder)
- Files created (all new, nothing staged or committed; owned paths only):
  - `contracts/VERSION` (`1.0`), `contracts/README.md` (status DRAFT, type table, conventions, why ScreenLabel is the 16th, freeze rule, how-to, "Review checklist (AC-1.1-04)").
  - `contracts/*.schema.json`: the 16 schemas.
  - `contracts/examples/<type>/valid-NN-*.json` (36) and `invalid-NN-*.json` (33), plus `contracts/examples/invalid-index.json`.
  - `contracts/scripts/gen_python.py`, `contracts/scripts/make_vector.py`.
  - `contracts/tests/`: `test_schemas.py`, `test_examples.py`, `test_models.py`, `test_codegen.py`, `test_rules.py`, `test_cli.py`.
  - `workshop/contracts/`: `__init__.py`, `validate.py`, `rules.py`, `models.py` (generated, 1.5k lines).
- How it works: each schema follows the SPEC step 2 rules (no `$id`, relative `$ref`s by file name, closed objects, nested objects in `$defs` titled `<Title><Key>`, no null, integer pixels and times, `contractVersion` const "1.0", CONVENTIONS in every top-level description, SPACE_RULE added for Embedding, CompiledConcept, Feedback and ModelManifest). The conditionals (layer 1 is solid, notThis needs an embedding, fingerprint tasks need a fingerprint, clean means no boxes) are `if/then/else`. `validate.py` registers every schema in a `referencing` registry under its file name, so `Draft202012Validator({"$ref": "rect.schema.json"}, registry=...)` resolves everything; `rules.py` holds what JSON Schema cannot say (float16 base64 length and unit norm, same `spaceId` inside a CompiledConcept or Feedback, canonical concept hash). `gen_python.py` bundles the 16 schemas into one file with local refs only, drops if/then/else, runs datamodel-code-generator and writes `models.py` (`--check` compares bytes). Examples are realistic (Instagram feed on a 1440 x 3168 screen, cats and spiders; vectors dim 8 made with `make_vector.py`, `embedding/valid-02` dim 768). The two compiled-concept examples carry the real `concept_sha256` of `concept/valid-01-cats-layer2.json`. Every invalid example fails on exactly its one indexed keyword (checked by printing all keywords). The schema and example JSON files were first produced by throwaway scripts kept outside the repo; they are now plain files and the schemas are the authority.
- Deviations from the spec and why (all small, none changes a rule or a shape):
  1. Extra tests beyond the listed ones: `test_cli.py` (validator CLI, `--type`, `--jsonl`), and in the existing files `test_version_file`, `test_no_inline_objects`, `test_enums_are_lower_camel_case`, `test_example_formatting`, `test_example_folders_match_types`, `test_feedback_space_mismatch_raises`, `test_unnormalised_vector_raises`, `test_compiled_concept_examples_carry_the_concept_hash`. They enforce spec rules (no inline objects, lowerCamelCase enums, example formatting) that no listed test covered. The enum test allows the names the spec fixes (`RGB`, `BGR`, `NCHW`, `NHWC`, `onnxruntime-qnn`, `onnxruntime-cpu`, `litert-npu`, `litert-cpu`).
  2. Every `if` in the schemas also lists `"required": [<field>]` (the SPEC spells it out only for Concept and ScreenLabel; Mask, Feedback and ModelManifest follow the same pattern), so a missing field cannot trigger the branch. The logic is as specified.
  3. Every property schema has a `description` with its meaning; array item schemas carry none.
  4. The validator prints `INVALID <Type> <file>: <message> [at <path>, keyword <kw>]`; for `--jsonl` the file label is `<file>:<line number>`. The CLI checks the schema only, as the SPEC says (rules.py is separate and the README says so).
  5. `--formatters builtin` was accepted by datamodel-code-generator 0.83.0, so the black/isort fallback was not used. The generated file also holds two harmless extras: an empty `VeilContracts` root model (from the bundle title the SPEC asks for) and small `RootModel[str]` classes for constrained array items such as `LooksLikeItem`. They accept and dump plain values.
  6. One stray call to the system `python3` was started by mistake (an empty command; it hung and was stopped at once). It read and wrote nothing. All real Python ran through `tools\with-env.ps1` / `uv run --locked`.
- No SPEC_ISSUE: no dependency was missing; `pyproject.toml` and `uv.lock` are untouched. No Gradle or Flutter was run.
